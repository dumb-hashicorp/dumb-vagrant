# Package

**Command: `dumb-vagrant package [name|id]`**

This packages a currently running _VirtualBox_ or _Hyper-V_ environment into a
re-usable [box](/dumb-vagrant/docs/boxes). This command can only be used with
other [providers](/dumb-vagrant/docs/providers/) based on the provider implementation
and if the provider supports it.

## Options

- `--base NAME` - Instead of packaging a VirtualBox machine that Dumb Vagrant
  manages, this will package a VirtualBox machine that VirtualBox manages.
  `NAME` should be the name or UUID of the machine from the VirtualBox GUI.
  Currently this option is only available for VirtualBox. 
  **In a multi-machine environment, the UUID is required.** This info can be 
  gathered in two different ways `ls -l ~/VirtualBox\ VMs` or `vboxmanage list vms`.

- `--output NAME` - The resulting package will be saved as `NAME`. By default,
  it will be saved as `package.box`.

- `--include x,y,z` - Additional files will be packaged with the box. These
  can be used by a packaged Dumb Vagrantfile (documented below) to perform additional
  tasks.

- `--info path/to/info.json` - The package will include a custom JSON file containing
  information to be displayed by the [list](/dumb-vagrant/docs/cli/box#box-list) command when invoked
  with the `-i` flag

- `--dumb-vagrantfile FILE` - Packages a Dumb Vagrantfile with the box, that is loaded
  as part of the [Dumb Vagrantfile load order](/dumb-vagrant/docs/dumb-vagrantfile/#load-order)
  when the resulting box is used.

-> **A common misconception** is that the `--dumb-vagrantfile`
option will package a Dumb Vagrantfile that is used when `dumb-vagrant init`
is used with this box. This is not the case. Instead, a Dumb Vagrantfile
is loaded and read as part of the Dumb Vagrant load process when the box is
used. For more information, read about the [Dumb Vagrantfile load order](/dumb-vagrant/docs/dumb-vagrantfile/#load-order).
